# Oko RAG Module

Локальный RAG без облака. Embeddings и генерация — через уже установленный Ollama.

## Структура

```
oko_rag/
├── config.py       # пути, модели, параметры чанкинга
├── loader.py       # чтение PDF/TXT + чанкинг
├── embeddings.py   # обёртка над Ollama /api/embeddings
├── indexer.py       # индексация документов в ChromaDB
├── retriever.py     # семантический поиск + сборка контекста
├── cli.py            # вопрос -> контекст -> ответ модели
├── documents/       # сюда кладёшь файлы для индексации (создастся сама)
└── chroma_db/        # персистентная векторная БД (создастся сама)
```

## Установка

Активируй окружение `oko_bot` и поставь зависимости:

```
conda activate oko_bot
pip install -r requirements.txt
```

Модель эмбеддингов должна быть в Ollama:

```
ollama pull nomic-embed-text
```

Если чат-модель у Oko не `llama3` — поменяй `CHAT_MODEL` в `config.py`.

## Использование

1. Кинуть файлы (PDF/TXT/MD) в `oko_rag/documents/`.
2. Проиндексировать:

```
python indexer.py
```

Переиндексация файла (если он изменился) — просто запусти `indexer.py` заново, старые чанки этого файла удаляются автоматически (matching по имени файла).

3. Спросить напрямую, без похода в LLM (только для проверки поиска):

```
python retriever.py "как работает векторный поиск"
```

4. Полный цикл (retrieval + генерация):

```
python cli.py "какой у меня договор с поставщиком X"
```

## Интеграция в существующий сервис

В своём основном скрипте (том, что крутится через NSSM) просто импортируй:

```python
from retriever import build_context

context, hits = build_context(user_query)
# дальше context суёшь в промпт своей текущей логики вызова модели
```

Не обязательно тащить весь `cli.py` — он просто пример полного пайплайна.

## Важные ограничения текущей версии

- Чанкинг по символам, без учёта структуры (заголовков, абзацев). Для научных статей с чёткой структурой стоит доработать под chunking по секциям.
- `collection.delete(where={"source": fname})` матчит по имени файла — если два файла с одинаковым именем лежат в разных местах, это сломается. Держи документы в одной плоской папке или расширь метадату путём (`path` вместо/вместе с `source`).
- Нет дедупликации по содержимому — если один и тот же текст в двух файлах, оба проиндексируются.
- `TOP_K` и `max_chars` в `build_context` — тюнингуй под размер контекстного окна своей чат-модели.
