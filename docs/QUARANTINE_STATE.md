# Состояние карантина: суточный слепок, недельный слепок, зум

Модуль `src/quarantine_state.py`, CLI `tools/quarantine_state_cli.py`. Только стандартная библиотека; в службы не встроен,
расписание запуска — отдельно. Хранилище — отдельная SQLite-база (по умолчанию `data/state/quarantine_state.db`,
переопределение — `OKO_QUARANTINE_STATE_DB`).

## Вход

Каталог карантина: перенесённые файлы с сохранением относительных путей и `manifest.tsv`
(столбцы `path`, `size`, `sha256`, `reason`, `moved_at`, `quarantine_path`). Категория файла выводится из `reason`
по ключевым словам: `duplicate` (дубль / лишняя копия), `merge_source` (исходник склейки), `old_version`
(старая версия), `test_junk` (тестовый мусор / сирота без записи базы), иначе `other`; файл без строки манифеста —
`unlisted`.

## Уровень 1 — суточный слепок (`snapshot <dir>`)

Агрегат без содержимого и без имён файлов: число файлов и байт, файлы и байты по категориям, расширения,
`time_min` / `time_max` переноса (по манифесту, иначе mtime), число строк манифеста, `content_digest` —
sha256 от отсортированного списка sha256 файлов. Канонический JSON агрегата → `aggregate_sha256`;
`daily_uuid = uuid5(NAMESPACE, sha256(канонический JSON {day, dir, aggregate_sha256}))`,
`NAMESPACE = uuid5(NAMESPACE_URL, "oko:quarantine_state")`. Таблица `quarantine_state_snapshots`
(`daily_uuid` PK, `day`, `dir`, `created_at`, `aggregate_json`, `aggregate_sha256`, `ttl_h`, `purged_at`).
Повтор в те же сутки с тем же агрегатом — та же строка.

## Очистка (`purge <dir> [--dry-run]`)

Каталог удаляется только при двух условиях одновременно: есть слепок того же каталога с тем же агрегатом
(агрегат пересчитывается перед удалением) и возраст карантина (`now − time_max`) не меньше `ttl_h`
(по умолчанию 24 ч). Иначе — 0 удалений и причина: `no_snapshot`, `directory_changed_since_snapshot`,
`age_below_ttl`, `dry_run_would_delete`, `no_directory`, `refused_path` (корень диска, домашний каталог,
каталог с самим модулем).

## Уровень 2 — недельный слепок (`weekly [--end-day D] [--k 3]`)

Окно — 7 суток, заканчивая `end_day`; на сутки берётся последний слепок. Ряды метрик: `files`, `bytes`,
`cat.<категория>.files`, `cat.<категория>.bytes`. `weekly_uuid = uuid5(NAMESPACE, sha256(канонический JSON
{daily: [daily_uuid по дням], aggregate: {days, series, k}}))`; `partial = 1`, если суток меньше 7.
Точка спада — сутки, где значение метрики ниже медианы окна больше чем на `k · scale`; `scale` — MAD
(медиана абсолютных отклонений), при MAD = 0 — `max(1, 5 % медианы)`; при меньше чем 3 сутках правило не
применяется. Таблица `quarantine_state_weekly`.

## Уровень 3 — зум (`zoom <weekly_uuid>`)

Для каждой точки спада: сутки, `daily_uuid`, суточный агрегат и узлы отклонения — метрики и категории
(значение, медиана окна, разность). Окно сужается с недели до суток и до категории.

## Цикл расписания (`cycle --root DIR [--glob knowledge_*] [--weekly-on Sun|none] [--dry-run] [--log P]`)

Один проход для каждого каталога `DIR/<glob>`: `snapshot` (в пределах суток повтор не создаёт новую строку),
`purge` по правилу выше (`--dry-run` — только причина, без удаления; слепок пишется и в dry-run), в выбранный день
недели — `weekly` по последним 7 суткам. Вывод: строка JSON на каталог (`dir_name_sha16` вместо имени, `daily_uuid`,
число файлов, итог `purge`) и строка итога цикла; те же строки дописываются в лог (по умолчанию
`logs/quarantine_state.log`). Запуск по расписанию настраивается вне модуля (планировщик ОС).

## Метрики прогонов блоков (`record-run <file.json | ->`, таблица `run_metrics`)

Запись прогона — только числа и коды: `task` (код задачи, `B15`), `block` (`run`, `elevated`, `verify`, `st`…),
`started_at` / `ended_at` (ISO 8601), счётчики `steps`, `rollbacks`, `uac`, `hitl`, `parse_errors`, `net_errors`,
`flaky` (повторы упавших тестов в гейте; каждая повторная попытка — строка `FLAKY` в отчёте блока), `signal`
(1 / 2 / 3 / 5). Текст отчётов не хранится; лишние поля записи игнорируются. `run_id = uuid5(NAMESPACE,
sha256(канонический JSON {run: [task, block, started_at]}))` — повтор той же записи не создаёт строку. CLI принимает
объект или список; при ошибке любой записи (код 2) не пишется ни одна.

`weekly` добавляет по суткам ряды `run.count`, `run.duration_s`, `run.<счётчик>`, `run.green_pct` (доля прогонов
с сигналом 1) и `run.clean_pct` (доля прогонов без откатов, FLAKY, ошибок разбора и сети), в процентах — в тот же
поиск точек спада (`k · scale`). Сутки только с прогонами (без слепка карантина) входят в окно с `daily_uuid = null`;
без строк `run_metrics` недельный слепок прежний.
