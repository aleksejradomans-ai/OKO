# DECISIONS — журнал архитектурных решений «Око» (Система 0)

Формат записи: решение → почему (данные) → коммит → когда пересмотреть.
Комментарии в коде со ссылкой «см. историю решений» указывают сюда (ADR-NNN).
Записи не переписываются задним числом: устаревшее решение помечается
«заменено ADR-NNN», новое добавляется в конец.

---

## ADR-001. Слой B: гигиена данных маскирует, а не блокирует (05.10.2026)
- **Решение:** `DataHygieneFilter` детерминированно маскирует технические артефакты
  (ключи, токены, пароли, карты с Luhn, IBAN, email, строки с высокой энтропией).
  Сообщение никогда не блокируется. Темы и смысл не оцениваются.
- **Почему:** тематический диспетчер блокировал сообщения целиком и оценивал
  «допустимость мыслей». Принцип: предупреждать о данных, не о мыслях.
- **Коммит:** `63a46c1`. Тесты: `test_data_hygiene.py` (16).

## ADR-002. Память не зависит от транспорта: MemoryCore (05.10.2026)
- **Решение:** журнал событий в `data/memory/memory.db`, ключ — локальный
  `subject_id`, а не Telegram ID. Индекс производный (сейчас `_NullIndex`).
- **Почему:** смена канала или рестарт не должны обнулять память.
- **Коммит:** `63a46c1`. Миграция `sessions` → `events`: 36 событий.

## ADR-003. Окончания строк: LF для кода, CRLF для Windows-скриптов (05.10.2026)
- **Решение:** `.gitattributes`: `* text=auto eol=lf`; CRLF для `.ps1 .bat .cmd .sln
  .vcproj .ahk` и для `security_tools/manifest.sha256`.
- **Почему:** `core.autocrlf` менял байты при checkout, и проверка `manifest.sha256`
  ложно срабатывала бы на защищённых модулях.
- **Коммит:** `c3763ec`, `7b2aeac` (манифест 13/13 OK), `69309db`.

## ADR-004. F1: транспортный сбой без рефлексии (06.10.2026)
- **Решение:** `LLMTransportError` (сеть, таймаут, 5xx) → сразу `[ERR: LLM_UNAVAILABLE]`,
  без `_meta_reflect` и без судьи. `LLMContentError` (4xx, схема) → рефлексия.
- **Почему:** таймаут перегруженной модели порождал ещё вызовы LLM и рост
  промпта: положительная обратная связь, до 3–4 минут на сообщение.
- **Коммит:** `65afe47`. Тесты: 41/41.

## ADR-005. Токен Telegram не попадает в логи (06.10.2026)
- **Решение:** логгеры `httpx`/`httpcore` на уровне WARNING.
- **Почему:** на INFO `httpx` писал полный URL с токеном раз в ~10 с. Токен перевыпущен.
- **Коммит:** `42db190`.

## ADR-006. RAG: порог релевантности 0.48 (06.10.2026)
- **Решение:** `OKO_RAG_MAX_DISTANCE=0.48` (cosine, `oko_knowledge_bge_m3`, `bge-m3`).
- **Данные:** содержательные запросы 0.34–0.44; пустые реплики 0.55–0.62 (6 запросов).
- **Почему:** без порога к приветствиям подмешивалась статья → петля P1.
- **Коммит:** `b7cbdbb`, `808f526`. **Пересмотреть:** при смене модели эмбеддингов
  или по логам `knowledge_len` через месяц.

## ADR-007. P1: предохранитель от самоповтора в памяти (06.10.2026)
- **Решение:** ответ, дословно повторяющий один из последних 10 на другой вопрос,
  не записывается в память (лог `P1 loop guard`).
- **Почему:** ошибочный ответ усиливал сам себя через историю (4 из 5 ответов —
  одно и то же). Отравленная история очищена (28 событий).
- **Коммит:** `f833013`.

## ADR-008. Судья детерминирован: temperature=0 (06.10.2026)
- **Решение:** `_verify_compliance` и `_self_correct` с `{"temperature": 0, "seed": 0}`.
  Основная генерация — без изменений.
- **Данные:** до правки 4 прогона давали 4 разных ответа; после — вердикты 3/3 стабильны.
  Остаточная вариативность текста — между запусками раннера Ollama, не внутри.
- **Коммит:** `41b2caa`.

## ADR-009. Промпт судьи J1 принят, J2 отклонён (06.10.2026)
- **Решение:** уточнения J1 (числа не нарушение; POL_001 = эмоции / совет без
  основания / искажение ради успокоения; противоречие приоритетнее; иначе PASS).
- **Данные:** 14/17 → 17/17; со слепыми и отложенными кейсами 28/29. J2 (примеры
  в промпте) — 28/29, прироста нет → отклонён.
- **Правило:** правка промпта принимается только при измеримом приросте на
  `eval/judge_cases.json`, без ложных срабатываний на контроле.
- **Коммит:** `67f9cd6`, `f4a945c`, `80cdc19`, `91e7832`, `c17b838`.

## ADR-010. `f_referral` = FAIL (06.10.2026)
- **Решение:** «обратитесь к специалисту» без фактического основания — нарушение POL_001.
- **Почему:** решение владельца правил.

## ADR-011. Тесты не касаются боевых данных (06.10.2026)
- **Решение:** `conftest.py` (корень и `src/`) принудительно ставит `AI_BASE_DIR`
  во временный каталог до загрузки тестов.
- **Почему:** `.env` направлял тесты в `C:\oko\data`; тесты **удаляли**
  `registry_state.json` — отсюда «обнуления» аудиторских счётчиков.
- **Коммит:** `5e9465b` (сломан), `99a7b0f` (исправлен через AST).

## ADR-012. Время в тестах — ручные часы (06.10.2026)
- **Решение:** `circuit_breaker._now()` подменяется в тестах; `sleep` заменён на `_advance`.
- **Данные:** было 5 падений из 30 (шаг таймера Windows ~15.6 мс), стало 0/30.
- **Коммит:** см. `git log` («Circuit breaker: injectable clock»).

## ADR-013. Структурные проверки вне судьи, только наблюдение (06.10.2026)
- **Решение:** `structural_check.py`: пустой ответ, обрыв, язык, утечка инструкций,
  арифметика (точно, через `Fraction`). Лог `STRUCT point=A|B kind=…`.
  Поведение не меняется.
- **Почему:** судья видит только текст ответа и не должен проверять факты.
  Точка B обязательна: дефекты наблюдались в выходе коррекции.
- **Коммит:** `403a0bb`, `6d967f7`. **Пересмотреть:** по статистике `STRUCT`.

## ADR-014. Русский по умолчанию, другой язык — по явной просьбе (06.10.2026)
- **Решение:** `identity.md`: «Другой язык — только если Оператор прямо попросил».
  Проверка языка пропускается при явной просьбе (включая опечатку «енглийском»).
- **Почему:** правило писалось против самовольного перехода на английский.
- **Коммит:** `266db48`, `e07f46f`. Мёртвая копия `identity.md` в корне удалена: `e093d4c`.

## ADR-015. Факты о системе — детерминированно, не от модели (06.10.2026)
- **Решение:** `/memory` (из `inventory()`), `/status` (без падений), общий
  обработчик ошибок, понятный текст для `[ERR: …]`, подпись `[Око]`.
- **Почему:** аудит 06.10 — модель уверенно заявляла «личные данные не хранятся»
  и «лог в db.py». Модель не видит состояния системы и не должна о нём говорить.
- **Коммит:** `e07f46f`.

## ADR-016. LLM_TIMEOUT = 90 с (06.10.2026)
- **Решение:** `.env`: `LLM_TIMEOUT=90`. Судья — отдельно, 15 с.
- **Данные:** вопрос 867 симв. + 10 сообщений истории + 1169 симв. RAG не уложился в 30 с.

## ADR-017. R1: удаление только явное (06.10.2026)
- **Решение:** `/forget` → превью; `/forget confirm` → удаление + `wal_checkpoint(TRUNCATE)`
  + `VACUUM` + чистый снапшот. TTL выключен (`OKO_MEMORY_TTL_DAYS=0`), умолчание
  в коде тоже `0`: автоудаление по сроку включается только явно.
- **Почему:** решение Оператора хранить историю; умолчание 30 при потере строки
  в `.env` стёрло бы историю без согласия.
- **Проверено:** после `/forget confirm` фраз из истории нет ни в одном файле `data/`.
- **Коммит:** `41497e6`, `2af48a7`.

## ADR-018. Операционная безопасность (06.10.2026)
- Файлы с перепиской, базы, `.env` и логи **не выгружаются** во внешние сервисы
  (чаты, облака). Для отладки — счётчики, схемы, выводы команд.
- Выгрузка кода — только `git archive` (исключает `.env`, `data/`, `logs/`).
- Ручные копии баз (`*.before_cleanup` и т. п.) — вне `C:\oko\data` или удаляются
  сразу: `/forget` их не видит.
- PowerShell 5.1: конфиги для Python пишутся без BOM
  (`[IO.File]::WriteAllText(…, New-Object Text.UTF8Encoding $false)`); блоки
  команд начинаются с `$ErrorActionPreference = "Stop"`.

## ADR-019. Судья fail-closed при обрыве связи (17.10.2026)
- **Решение:** таймаут, обрыв или 5xx во время проверки, коррекции или повторной
  проверки → `_transport_failure` → `[ERR: LLM_TIMEOUT]` / `[ERR: LLM_UNAVAILABLE]`;
  ответ не отдаётся.
- **Почему:** раньше ответ уходил непроверенным. При `GPU_CONCURRENCY=1` судья
  истекал по `JUDGE_TIMEOUT`, стоя в очереди за чужой генерацией: проверку
  обходила любая параллельная нагрузка (воспроизведено тестом).
- **Коммит:** `a08fec4`. Тесты: `test_judge_transport.py` (8).

## ADR-020. `patch_applier._commit` не теряет исходную ошибку (17.10.2026)
- **Решение:** сбой `rollback()` → CRITICAL с `exc_info` + `add_note`; сбой уборки
  tmp → WARNING, откат всё равно выполняется; наружу — исходная ошибка записи.
- **Коммит:** `d9b579e` (манифест обновлён, 13/13).

## ADR-021. Чат только для `ADMIN_USER_IDS` (17.10.2026)
- **Решение:** `handle_message` молча игнорирует посторонних до фильтра, LLM, RAG,
  памяти и мониторов; WARNING с id и длиной, без текста. Пустой список — бот молчит
  для всех (WARNING при старте). `/memory` и `/forget` работают только с памятью
  самого пишущего.
- **Почему:** проверка была только в командах; любой мог тратить GPU и вытягивать
  RAG-контекст вопросами.
- **Коммит:** `eae1f39`.

## ADR-022. Судья fail-closed по содержанию (17.10.2026)
- **Решение:** нераспознанный вердикт → `[ERR: JUDGE_UNPARSEABLE]` (жёлтый);
  FAIL после коррекции или сбой коррекции → `[ERR: COMPLIANCE_UNRESOLVED]` (красный).
  Служебных кодов стало 12.
- **Почему:** «fail-safe» парсера на деле был fail-open: ERROR отдавал ответ, а текст
  с подтверждённым нарушением уходил как best-effort. Решение Оператора.
- **Цена:** судья детерминирован, поэтому на одном и том же тексте отказ повторяется.
- **Не изменено:** нетранспортное исключение при вызове судьи → ответ UNCHECKED.
- **Коммит:** `31ddf8e`. Тесты: `test_judge_fail_closed.py` (13).

## ADR-023. Консольный контур выведен (17.10.2026)

## ADR-024. Слой guardrails выведен (17.10.2026)
- `guardrails.py` (`AntiEgoQuarantineShield`) и `reality_privacy_dispatcher.py`:
  результат `initialize_guardrail()` не использовался, входной фильтр —
  `DataHygieneFilter` (ADR-001). Бот больше не требует `rules.json`.
  **Коммит:** `91c8994`.

## ADR-025. Тесты не читают `.env` (17.10.2026)
- **Решение:** `src/conftest.py` задаёт фиктивный `TELEGRAM_TOKEN` и пустой
  `ADMIN_USER_IDS` до импорта `config`.
- **Почему:** тесты подхватывали настоящий токен и список админов, а в чистом клоне
  без `.env` падали на импорте `config`. **Коммит:** PUBLISH_PREP.

## ADR-026. Судья: описание правил — не нарушение; мимо судьи только точный маркер (14.10.2026)
- **Решение:** в промпт судьи добавлен пункт «описание правил и служебных кодов —
  не нарушение» (в рабочих заметках тоже назывался J2; не путать с J2 из ADR-009).
  Мимо судьи проходит только текст, целиком равный известному маркеру `[ERR: КОД]`;
  раньше — любой текст, начинавшийся с `[ERR:`.
- **Почему:** на вопрос «что такое HALT_CONDITION?» судья блокировал описание правила
  POL_002 как его нарушение; при `temperature=0` ложный HALT повторялся всегда.
  Префиксная проверка позволяла провести ответ мимо судьи, начав его с `[ERR:`.
- **Данные:** A/B на живой Ollama, 12 текстов (`eval/eval_judge_variants.py`):
  исходный промпт — 2 ложных срабатывания, с новым пунктом — 0 ложных и 0 пропусков.
  Корпус мал; каждый не-PASS вердикт пишется в лог `[JUDGE_TRACE]`.
- **Коммит:** `8ac9c3a`, `c1fafec`, `98037d9` (`test_marker_gate.py`, 16 тестов).

## Известные ограничения (не решения, а открытые вопросы)
- ~~`circuit_breaker.py` не подключён к `AgentGovernor`~~ — подключён (`39249a4`).
- Судья проверяет арифметику через HALT (неверная формула = «противоречие»);
  `ctl_arith` — пограничный кейс, может переворачиваться между запусками Ollama.
- Индекс памяти — `_NullIndex`: бот видит только 10 последних сообщений.
- Весь ввод проходит через серверы Telegram до любых фильтров (T1).
- Модель склонна к непрошенным советам; судья их не ловит.
- Время в логах ПК на 1 час впереди времени телефона (разные часовые пояса).
- `AntiEgoQuarantineShield` (F3) — выведен (ADR-024). Пакет `src/` и `sys.path` (L1) — не разобраны.
