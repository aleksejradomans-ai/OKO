# ADR-027. «Алгоритм винегрета»: пространство намерений и память паттернов G6 (10.11.2026)

- **Решение:** пакет `src/oko/` по спецификации v1.0: детерминированный `VectorParser`
  (T × A × P × M, без LLM), `PatternEngine`/`CrystallizationEngine` (память Оператора),
  `CalibrationEngine` (порог 60 %), `CommandRouter` со сверкой фактического состояния,
  `EventRegistry` и `PatternRepository` на SQLite. К боту и реальным устройствам не подключён:
  исполнение идёт через протокол `DeviceAdapter`.
- **Почему:** три контура разделены — распознавание, исполнение, обучение, — чтобы успешное
  срабатывание устройства не считалось доказательством правильности распознавания.
  G6 — свёртка событий `EVIDENCE` из журнала, поэтому память пересчитывается и откатывается.
- **Отступления от текста спецификации:**
  - ключ паттерна — `Hash(O, t, a, Schema(p))` без `Template(S)`: иначе «включи свет» и
    «зажги люстру» дали бы две записи вопреки §6 и §8; шаблон различает псевдонимы внутри паттерна;
  - добавлен статус `CANDIDATE` (наблюдался, но подтверждённого проверенного исполнения нет);
  - псевдоним — шаблон реплики целиком, не отдельное слово: «вруби телек» и «выруби телек»
    подтверждаются по отдельности;
  - уточнение не считается промахом парсера в `A_N`: промах — когда Оператор изменил координату,
    которую парсер утверждал. Строгое чтение включается `Settings(clarify_is_miss=True)`;
  - морфология — закрытая таблица словоформ встроенных словарей, без внешних библиотек.
- **Следствие:** устройство без обратной телеметрии даёт `ACKNOWLEDGED`, и его паттерны
  не кристаллизуются никогда — так требует §6.4.

## Правки по ревью ROLE_R2 v2

- **Транслит.** Неоднозначная латинская буква даёт кандидатов (`c` → ц|ч, `w` → ш|щ, `i` → и|ы,
  `y` → ы|и), `h` → х, `j` после согласной → ь. Выбирается прочтение, которое есть в словарях;
  нет ни одного — первое по таблице. Диграфы (`ch`, `sh`, `ju`…) пробуются раньше одиночных букв.
- **Опечатки.** Нечёткий поиск `d_L <= 1` идёт после выбора прочтения транслита и с длины 4
  (в спецификации — 5). Он учитывает и остальные прочтения: если они ведут к разным леммам,
  слово остаётся неоднозначным и команда не исполняется.
- **Предмет.** Голое «лампа / лампы / лампочки» неоднозначно (`tv_amb` или `lamps`) → `CLARIFY`:
  в доме это и светодиоды подсветки ТВ, и лампы на потолочной штанге. `lamps` — только
  «люстра, потолок, потолочный, штанга, планка, верхний свет». «Торшер» из встроенного словаря
  убран — появляется только через обучение Оператором. Привычку Оператора («лампы» = подсветка)
  закрепляет кристаллизация. Приёмочный тест T02 поэтому идёт на «зажги люстру», а не «зажги лампы».
- **Срок жизни запроса.** `CLARIFY`/`CONFIRM` живут 90 с (`Settings.pending_ttl_s`), часы — те же
  инжектируемые, что у журнала. Опоздавший ответ → `EXPIRED`, событие `REQUEST_EXPIRED`,
  исполнения нет.
- **Опасные команды.** `HomeConfig.confirm_required` (по умолчанию выключение ТВ) всегда идёт
  через `CONFIRM`, даже для кристаллизованного паттерна и после ответа на уточнение.
  `CommandRouter` сам отказывает неподтверждённой опасной команде. Отказ Оператора — `cancel()`.

**Тесты:** `src/test_vinaigrette.py` (T01–T10, инварианты §16, правки ревью).

## Правки №1 и №2 до R2c (11.11, решения Оператора 23:15 п.5 и п.1)

- **№1. Обучение только явное.** Связка (псевдоним «реплика → команда») заводится и закрепляется
  только свидетельством `remember=True`: `Vinaigrette.remember(command_id)` — кнопка
  «Запомнить связку», позже на R2c — «запомни: X — Y». Только при результате `VERIFIED`;
  иначе `NOT_VERIFIED` («Результат не подтверждён устройством. Связка не сохранена.»), событие
  `BIND_REFUSED`. Выбор варианта в «❓ Уточни», подтверждение `CONFIRM` и метка `confirm()`
  связку не создают: остаются наблюдением, отсчётом точности (`VALIDATION`) и меткой качества q.
  Прежнее поведение: `ALIAS_ADDED` на каждое исполнение, выбор в «❓ Уточни» = `validated`.
- **№2. Лимит и вытеснение.** `Settings.bind_limit = 500` связок на Оператора (вместо TOP-32 на
  паттерн по частоте). Полная таблица → `PatternEngine.record` отказывает (`BindTableFull`, в журнал
  ничего не пишется) → вопрос `EVICT` Оператору: «Таблица связок полна: {n}. Самая старая: «{alias}».
  Заменить?». «Да» (`resolve`) → `BIND_EVICTED` в журнал и новая связка; «нет» (`cancel`) → ничего
  не меняется. «Самая старая» — по последнему использованию (LRU: `seq` = id события журнала, его обновляет
  каждое исполнение этой реплики и каждое «Запомнить»; не время — на Windows метки совпадают в пределах тика часов). `BIND_EVICTED` переигрывается при пересчёте памяти;
  откат через него возвращает связку.
- **Кристаллизация с одного нажатия** (решение 23:15 п.5, подтверждено Оператором 11.11 10:45):
  `cryst_min_confirmed=1`, `cryst_min_sessions=1`, `cryst_q=0.60`. Одно «Запомнить» с `VERIFIED` →
  `CRYSTALLIZED` (q = 2/3), реплика дальше исполняется без «❓ Уточни». Один отказ Оператора после
  этого → q = 0.5 → `DEGRADED`. Спецификация v1.0 требовала 3 исполнения в 2 сессиях и q ≥ 0.80 —
  это была механика неявного обучения, она убрана. Опасные команды (`confirm_required`) по-прежнему
  идут через `CONFIRM`; в режиме калибровки повышение статусов заморожено.
- **Два разных момента** (P0.3): давность для LRU (`seq`) — каждое исполнение
  реплики и каждое «Запомнить»; закрепление связки — только «Запомнить» после `VERIFIED`.
- **Повтор нажатия** (P1.1, двойная доставка Telegram) → `ALREADY`, в журнал ничего не пишется.
- **Замена — одна транзакция** (P0.2): сбой между `BIND_EVICTED` и новой связкой → `rollback`,
  старая связка остаётся.
- **Совместимость журнала:** старые `EVIDENCE` без поля `remember` при пересчёте связок не дают.
  Боевых журналов пакета нет — к боту он не подключён.

## R2c — подключение к боту: связки поверх правил (11.11, решение 13:1x, вариант 1)

- **Два слоя.** Слой 1 — штатные `router.route` / `tv_commands` / `tv_bot_handler.handle()` с подтверждением опасных
  команд: исполнение и обратная связь, не тронуты. Слой 2 — `oko.memory.BindMemory`: фраза Оператора → готовая
  штатная команда. `VectorParser` и `DeviceAdapter` пакета к боту не подключаются.
- **Хранение:** `data\memory\g6.db` (рядом с memory.db, отдельный файл), `check_same_thread=False` + RLock.
  Связка = паттерн (target = штатная команда, action = `cmd`) + псевдоним (template = фонетический ключ фразы,
  `layout_fix.phonetic_key` без стоп-слов; `phrase` — как сказано, для текстов).
- **Где применяется** (`bind_layer.can_apply`): правила вернули модель (BRAIN) или уточнение `clarify:*` / `lamps:which`.
  Не перекрывает: запрет (C4), «запомни …» (C7), миф (C9), лампы потолка (R2b), вопрос «?», самоотмену, штатную команду.
- **Исполнение по связке** — только `run_tv` → `handle()`; заметка «Понял как «Y» (связка).», кнопка «✖ Не то» → отказ
  Оператора → q 0.5 → DEGRADED, автоприменения нет.
- **Статус для памяти** (`bind_layer.exec_status`): PASS → VERIFIED; PASS слепой кнопки («Отправил…», PREFIX_NOTE_BLIND)
  → ACKNOWLEDGED; WARN → MISMATCH; FAIL → FAILED; не исполнено → не пишется.
- **Обучение:** «❓ Уточни» → кнопки вариантов (только исполнимые штатные команды); выбор исполняется, но связку не
  создаёт; при VERIFIED — кнопка «📌 Запомнить связку». «запомни: X — Y»: Y — штатная команда без подтверждения
  (standby не закрепляется), X не занят правилами, Y исполняется, связка — при VERIFIED. Полная таблица → «Заменить» /
  «Оставить». Повтор нажатия → то же «Связка сохранена» без записи. Окно Ока (shell) кнопок не видит — там работает «запомни: X — Y».
- **Отказоустойчивость:** любой сбой памяти связок → журнал `[BIND]`, маршрут как до R2c.
- **MEM_TEXT** → «Не сохранено. Формат: «запомни: фраза — команда».» (прежний текст «ещё не подключено» после R2c ложен).

## R2c_FIX2 — связка принадлежит фразе (11.11 вечер, red-team Fable: claude/FINDINGS_2026-11-11_fable_r2c.md)

- **Фраза → одна команда.** `remember` той же фразы на другую команду снимает прежнюю связку фразы в той же
  транзакции (`BIND_EVICTED reason=rebind`) — F01/F02 (раньше: две рабочие записи → «неоднозначно» → фраза молчит).
- **«✖ Не то» — по фразе.** Снимается связка ЭТОЙ фразы с этой командой (`BIND_EVICTED reason=reject`); q команды
  не трогается, другие фразы той же команды работают (F03/F04/F05). «отключена» — только если `lookup` правда пуст.
- **Одна команда справа** (F06): ни одно начало правой части не разбирается в действие (запрос `*_get` — не
  действие), «не» справа — отказ; та же проверка для уже сохранённых связок при применении.
- **Наблюдение — только для связанной фразы** (F21): штатные команды без связки не пишут паттерн/снимок, фраза не
  оседает в журнале.
- Кнопки: вариант «▶» гасится при первом взятии (F07); `r/x/e/k` сверяют нажавшего с владельцем (F08); сбой памяти не
  прячет ответ исполненной команды (F09), «запомни» при сбое памяти — «память связок недоступна» (F10); повторное
  «Заменить?» с полной таблицей — новый вопрос с кнопками, пустое `BIND_EVICTED` не пишется (F11).
- Ключ: стоп-слова по исходному слову (F13), латинская w = ш (F14); «запомни что X …» (F17); фраза ≤ 60 знаков (F18).
- Отложено (xfail в src/test_bind_fable.py): F12 свёртка ж/з ш/с в ключе, F15 кнопки в окне Ока, F16 спящий
  (rollback в боте не вызывается), F19 причина отказа, F20 слой 1 — решение Оператора, B01 выдуманный статус ТВ — отдельно.
