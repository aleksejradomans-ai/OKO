# Границы доверия и данные движка «Око»

Контракт без рекламы: что уходит наружу, чего система не обещает и где лежат данные. Каждое ограничение описано по
шаблону **что происходит по факту → в чём риск → как это бьёт по владельцу**. Пути — относительно каталога данных
движка (`data/`) или профиля пользователя, без привязки к конкретной машине. Правила с номерами — `docs/INVARIANTS.md`,
доказательства по каждому правилу — `docs/CONTROL_MAP.md`.

«Всё хранится локально» — неверно без оговорок. Локально лежат базы и журналы из раздела 3; наружу уходит то, что
перечислено в разделе 1.

## 1. Границы доверия и внешние контуры

### Чертёж

| контур | модуль (`src/`) | что уходит наружу | когда включён |
|---|---|---|---|
| Telegram | `bot.py` (python-telegram-bot) | весь ввод владельца и все ответы бота проходят через серверы Telegram **до** любых локальных фильтров | всегда, пока работает бот |
| Облако SmartThings | `device_watch.py`, `smartthings_oauth.py`, `smartthings_probe.py`, `st_*.py` | опрос состояния стиральной и сушильной машины (только чтение) не чаще раза в 30 с; обмен и обновление токенов OAuth; пробы `st_mode_walk.py`, `st_full_walk.py`, `st_option_probe.py`, `st_power_test.py`, `st_pause_test.py` **отправляют машине команды** | есть токен в окружении или файл токенов в каталоге данных |
| Облако Garmin | `garmin_sync.py`, `garmin_report.py` (неофициальная библиотека garminconnect) | вход и выгрузка показателей здоровья; сводки по расписанию | есть файл токенов Garmin в каталоге данных |
| Облако Roborock | `robo_cloud_inventory.py` (python-roborock) | разовая выгрузка списка устройств и ключей; результат — файл в профиле пользователя вне репозитория | только ручной запуск |
| Облако Midea | `midea_heater.py` | один раз — получение ключа устройства; дальше чтение только по локальной сети | только ручной запуск получения ключа |
| Шлюз в интернет | `net_gateway.py` | только GET по https с проверкой сертификата, хост и путь — из белого списка `config/net_allowlist.json`, лимиты частоты и размера, журнал запросов | закрыт по умолчанию: открыт только при `OKO_NET_OPEN=1` и без файла-рубильника |
| Языковая модель | `governor.py` (Ollama) | запросы к модели по адресу из `OLLAMA_HOST` (по умолчанию `localhost`) | всегда; наружу — только если адрес модели сменить на внешний |
| Домашняя сеть | `tv_control.py`, `amb_music.py`, `onvif_ro.py`, `ipp_probe.py`, `doc_print.py` | команды телевизору и лампам, чтение камеры (только запросы чтения), печать — в пределах локальной сети | по командам владельца |

**Зачем это владельцу / Не менять без [1]:** таблица — полный список того, что выходит за пределы дома; новый
сетевой или облачный модуль без строки здесь — нарушение контракта.

### По-человечески

Бот живёт в Telegram, поэтому каждое сообщение владельца сначала попадает на серверы Telegram и только потом — в
домашние фильтры. Часть техники (стиральная машина, часы, робот-пылесос) работает через облака производителей, и
данные о ней проходят через эти облака. Всё остальное — модель, базы, журналы — остаётся дома, пока владелец сам не
поменяет настройки.

## 2. Чего система НЕ гарантирует

| что происходит по факту | в чём риск | как это бьёт по владельцу |
|---|---|---|
| Сообщение проходит через серверы Telegram раньше, чем его увидит любой локальный фильтр. | Текст сообщения, включая случайно отправленный пароль, уже у стороннего сервиса. | Удалить сообщение из истории Telegram — забота владельца; бот этого не делает. |
| Проверка ответа («судья») — второй вызов той же небольшой модели, а не независимый контролёр. | Нарушение правил может пройти, безобидный ответ — быть заблокирован. | Ответ, прошедший проверку, всё равно может быть неверным; непрошенные советы ловятся не всегда. |
| Длинный ответ проверяется по кускам; противоречие между далёкими друг от друга кусками проверка не видит. | Ответ из согласованных по отдельности частей может противоречить сам себе. | Длинные ответы требуют внимательного чтения. |
| Ответы, собранные кодом (команды телевизору, шаблоны о самой системе, ответы на «запомни …»), и текст, целиком равный служебному коду ошибки `[ERR: КОД]`, проверку ответа не проходят — так задумано. | Ошибка в шаблоне или в коде маршрута уходит владельцу без второй проверки. | Неверная формулировка шаблона видна только при чтении кода и тестов. |
| Долговременного поиска по памяти диалога нет: в контекст попадают только последние 10 сообщений (индекс-заглушка `_NullIndex`). | Бот «не помнит» то, что было раньше этих 10 сообщений, хотя журнал хранится. | Повторять важное в начале нового разговора; «забыл» — не значит «стёр». |
| Песочница для проверки чужих правок убирает файлы секретов и секретные переменные, но диск и сеть дочернему процессу доступны. | Вредоносная правка может прочитать файлы вне песочницы по абсолютному пути или выйти в сеть. | Песочница — не защита от враждебного кода; чужие правки — только после чтения человеком. |
| Состояние `Registry` — JSON-файл без межпроцессной блокировки. | Два процесса одновременно могут перетереть запись друг друга. | Счётчики и статус могут отставать после одновременных запусков. |
| Пробы SmartThings из списка выше отправляют машине команды. | Ошибочный запуск пробы меняет программу или включает машину. | Пробы запускаются только вручную и только владельцем. |
| Потолок громкости 15 действует для знаковых команд («+3», «++»); обычное «громче» и «громкость 20» ограничены только общим пределом клиента телевизора. | Звук может стать громче 15 без переспроса. | См. расхождение по INV-19 в `docs/CONTROL_MAP.md`. |
| Удаление документа из базы знаний (`forget_document.py --apply`) сначала делает резервную копию базы знаний. | Текст удалённого документа остаётся в этой резервной копии. | Для полного удаления копию нужно удалить вручную. |

## 3. Реестр хранилищ данных

Названия — без путей конкретной машины; «каталог данных» — `data/` движка, «профиль» — каталог профиля пользователя.

| хранилище | категория данных | механизм удаления | что реально очищается |
|---|---|---|---|
| `memory.db` (`memory_core.py`) | журнал диалога: тексты сообщений и ответов по локальному `subject_id` | `/forget` → `/forget confirm`; срок хранения `OKO_MEMORY_TTL_DAYS` (0 = выключен) | события субъекта, журнал WAL и снимки базы стираются физически; при TTL — события старше срока |
| `g6.db` (`bind_layer.py`, `oko/memory`) | связки «фраза → штатная команда», журнал событий связок | «Не то» по связке, переучивание фразы, замена самой старой при полной таблице (с согласия) | снимается связка; журнал событий связок сохраняется (там же — факт вытеснения) |
| `consent.db` (`consent.py`) | журнал согласий: код вопроса, ответ [1]/[0], время, цепочка хэшей; без текста | нет (только добавление) | ничего: исправление — новой записью |
| `layer_events.db` (`layer_events.py`) | счётчики слоёв L0–L7: время, слой, вид, код события; без текста | механизма в коде нет | ничего; растёт до ручной очистки |
| `quarantine_state.db` (`quarantine_state.py`) | слепки каталогов карантина, метрики прогонов `run_metrics`, ночные счёта слоёв `layer_digest` | `purge` каталога карантина — только при совпадении слепка и истёкшем сроке | файлы каталога карантина; строки базы не удаляются |
| Теневой журнал Σ `sigma_shadow.jsonl` (`tv_bot_handler.py`) | поля белого списка (время, шаг, вид команды, признак, значения, исход, код, задержка, `seq`, вердикт) | ротация по размеру: один предыдущий файл `.1`, всего около 10 МиБ | самые старые строки при ротации |
| Состояние ядра Σ (`sigma_state.json`, `sigma_gate.py`) | счётчики и состояние тревоги | нет | ничего |
| `events.jsonl` (`event_log.py`) | события устройств и бота | механизма в коде нет | ничего |
| `sessions.jsonl` песочницы диалогов (`bot.py`, `sandbox_talk.py`) | реплики песочницы диалогов | механизма в коде нет | ничего |
| `ratings.jsonl` (`rating_log.py`) | оценки ответов: метка и комментарий владельца после метки (ограниченной длины) | механизма в коде нет | ничего |
| `knowledge_base.db` + ChromaDB (`knowledge_indexer.py`, `oko_rag`) | тексты одобренных документов, их куски и векторы | `forget_document.py --apply` | строки и векторы документа, его файлы в каталоге данных; **резервная копия базы перед удалением остаётся** |
| Карантин документов `staging/`, `incoming/` (`staging_manager.py`, `doc_intake.py`) | загруженные, ещё не одобренные файлы | Reject; `purge_old` для `incoming/` по возрасту | отклонённый или устаревший файл |
| `ops.db` (`ops_db.py`, `sleep_digest.py`, `hud_state.py`) | служебные метрики и ночные сводки | механизма в коде нет | ничего |
| `oko.db` (`garmin_sync.py`) | показатели здоровья из Garmin | механизма в коде нет | ничего |
| Журнал шлюза `net/journal.jsonl` (`net_gateway.py`) | время, метод, адрес, код ответа, байты, sha256, решение; без тела ответа | механизма в коде нет | ничего |
| Журналы процессов бота и наблюдателя | строки логов: id отправителя, длина и отпечаток ответа (сам текст ответа новые строки не пишут); в строках, записанных до перехода на отпечатки, тексты ответов могли остаться | ротация средствами запуска службы (вне кода) | зависит от настройки запуска; старые строки — только ручным удалением |
| Файлы токенов (SmartThings, Garmin, Roborock, телевизор) — в каталоге данных и в профиле | ключи доступа к облакам и устройствам | вручную | только то, что удалено вручную |

**Зачем это владельцу / Не менять без [1]:** новое хранилище без строки в этой таблице — нарушение контракта; у
каждого хранилища с текстом владельца должен быть понятный способ удаления.

### По-человечески

Переписку с ботом можно стереть командой, и она стирается по-настоящему, вместе с копиями. Многие журналы движок сам
не чистит — они растут, пока их не удалят вручную. Отдельно: в старых журналах бота могли остаться тексты ответов, а
удаление документа из базы знаний оставляет резервную копию базы — это нужно знать, если важно удалить «совсем».
